# リールのキャプションを書く

このリポジトリは動画を GitHub Pages に置いて Meta Graph API でリールとして投稿する。
その投稿に添える本文を用意するのがこのスキル。

```sh
./reel_post.sh publish takuha ~/Movies/reel001.mp4 "ここに入る文章"
```

## 最初に確認すること

本文を書く前に、次が分からなければ**書き始めずに聞く**。想像で埋めない。

1. **どのアカウントか**（`takuha` / `aoyagi`）。声のトーンが違う。
2. **動画の中身**。何が映っているか。ユーザーが説明していない場合は聞く。
   動画ファイル名だけから内容を推測しない。
3. **目的**。認知を取りたいのか、保存させたいのか、プロフィールに送りたいのか。

## 構成

リールのキャプションは上から順に効く。冒頭2行しか展開前に見えない。

1. **1行目（フック）** — 動画の内容を言い直さない。見た人が続きを知りたくなる一言。
2. **本文** — 3〜5行。1行は短く、改行を多めに。スマホの縦画面で読まれる。
3. **締め** — 行動を1つだけ書く。保存・コメント・プロフィールのどれか1つ。2つ以上は薄まる。
4. **ハッシュタグ** — 本文と1行空けてから。5〜10個。

## 文章のルール

- **句点で終わる短文を並べる。** 一文が2行を超えたら切る。
- **形容詞を削る。** 「すごく」「本当に」「とても」は消しても意味が変わらない。消す。
- **体言止めを連発しない。** 1投稿に1回まで。続くと広告の見出しになる。
- **「〜させていただきます」「〜となっております」を使わない。** 硬いのではなく他人行儀に読まれる。
- **絵文字は多くて3つ。** 意味を持たない絵文字は入れない。
- **書き出しに「みなさん、こんにちは」を置かない。** 1行目を挨拶で潰さない。

### AIっぽさが出る型（避ける）

以下はそのまま出すと生成物だと分かる。見つけたら書き直す。

| 出がちな型 | 直し方 |
| --- | --- |
| 「いかがでしたか？」 | 消す。問いかけるなら具体的に聞く |
| 「〜な方も多いのではないでしょうか」 | 断定に変える |
| 「ぜひチェックしてみてください」 | 何をどうしてほしいのか具体的に書く |
| 三点セットの列挙（「速い、安い、うまい」型） | 2つに削るか、1つに絞る |
| 「まとめ」「ポイント3つ」の見出し | リールの本文に見出しは要らない |

## ハッシュタグ

- **大中小を混ぜる。** 投稿数の多い一般タグだけだと埋もれる。
  内容に固有の小さいタグを必ず2〜3個入れる。
- **本文の意味と関係ないタグを足さない。** 到達は伸びず、アカウントの評価だけ下がる。
- **毎回まったく同じセットを使い回さない。** 動画ごとに半分は入れ替える。

## 渡し方

本文は `publish` の第3引数にそのまま渡る（`--data-urlencode` されるので改行も絵文字も
そのまま通る）。シェルから渡すので次に注意する。

- 全体を**ダブルクォートで囲む**。
- 本文に `"` `` ` `` `$` `\` が含まれるならエスケープするか、記号のほうを言い換える。
- 改行を含む本文はそのままクォート内で改行して構わない。

長い本文や記号が多い本文は、ファイルに書いて渡すほうが事故がない。

```sh
./reel_post.sh publish takuha ~/Movies/reel001.mp4 "$(cat caption.txt)"
```

## 出すときの形

書いたら、**そのままコピーできる形**で本文だけを提示する。解説を本文に混ぜない。
案を複数出すときは、フックの1行目だけを並べて選ばせてから、選ばれた案の全文を書く。
