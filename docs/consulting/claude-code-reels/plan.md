元ネタ: YouTube「【Claude Code完全入門】誰でも使えるツール／実行革命／ChatGPTとの違い／
５体のAIエージェントで実演／願望の質＝アウトプットの質／Skills活用法／経営者こそ使うべき／
言語化が全て」（2026年3月公開 / https://youtu.be/LRSSjGwsuv0 ）

> **注記**: 本編映像・字幕は取得できていない。本資料はタイトルに並んだ8つの論点と、
> Claude Code の実際の仕様をもとに構成している。元動画の固有のエピソードや数字を引用する
> 場合は、本編を見たうえで各台本の「差し替え枠」に入れること。

## 1. この動画から何を切り出すか

元動画のタイトルは、そのまま8つの論点リストになっている。これを「1本のリール＝1論点」に
割り当てるのがいちばん素直な分解になる。

| # | 元動画の論点 | リール化したときの中身 | 単体で成立するか |
| --- | --- | --- | --- |
| 1 | 誰でも使えるツール | 非エンジニアの入口。ターミナル恐怖症の解除 | ◎ |
| 2 | 実行革命 | 「提案するAI」から「実行するAI」へ | ◎ |
| 3 | ChatGPTとの違い | 会話の相手か、作業する相手か | ◎（2と統合可） |
| 4 | ５体のAIエージェントで実演 | 並列で走らせる。画が強い＝いちばん伸びる | ◎ |
| 5 | 願望の質＝アウトプットの質 | 欲しいものが曖昧なら出力も曖昧 | ◎ |
| 6 | Skills活用法 | 手順を1回書けば以後は言わなくていい | ◎ |
| 7 | 経営者こそ使うべき | 手を動かせない人ほど効く | ◎ |
| 8 | 言語化が全て | 5と同じ根。5の締めに吸収する | △（単体は弱い） |

→ **6本シリーズ**に再編する。3は2に、8は5に吸収。

## 2. シリーズ設計

| 本数 | タイトル（内部呼称） | 論点 | 尺 | 役割 |
| --- | --- | --- | --- | --- |
| R1 | AIが「提案」で止まる時代は終わった | 2 + 3 | 45秒 | 入口。いちばん拡散を狙う |
| R2 | コードが書けない人ほど得をする | 1 | 40秒 | 「自分ごと化」させる |
| R3 | AIを5体、同時に働かせる | 4 | 55秒 | 画で殴る。保存されやすい |
| R4 | 願望の質＝アウトプットの質 | 5 + 8 | 40秒 | 一番刺さる。引用されやすい |
| R5 | 一度教えたら、二度と説明しなくていい | 6 | 50秒 | 実用。フォローに繋がる |
| R6 | 経営者こそ、自分で触ったほうがいい | 7 | 60秒 | 締め。深い層に届かせる |

投稿順は R1 → R4 → R3 → R2 → R5 → R6 を推奨する。番号順ではない。
理由は、**R1（掴み）→ R4（刺さる）→ R3（画が強い）** の3本で最初の勢いを作りたいから。
R2・R5・R6 は伸びより「残る」側なので後半に置く。

間隔は中2日。毎日出すとシリーズ全体の到達が分散する。

## 3. ターゲットとトーン

**主ターゲット**: AIツールは触っているが Claude Code は未経験の層。ChatGPT は日常で使っている。
コードは書けない、または書けても本業ではない。

**副ターゲット**: 経営者・個人事業主。人を増やさずに手数を増やしたい人。

**トーン**:
- 「教えてやる」ではなく「これ知らないと損してる」の位置に立つ
- 専門用語は使ってよいが、使ったらその場で1行で言い換える
- 煽らない。誇張した数字を出さない。実際にやったことだけ喋る

**避けること**:
- 「これで年収が上がる」系の因果の飛躍
- 具体的な作業時間の削減率を根拠なく断言する（例:「作業時間が90%減」）
- 他ツールを名指しで下げる。ChatGPT との比較は「役割が違う」で通す

## 4. 共通フォーマット

| 項目 | 決め |
| --- | --- |
| 画面比 | 9:16（1080×1920） |
| 冒頭3秒 | 結論またはギャップだけ。挨拶・自己紹介は入れない |
| テロップ | 全編に焼く。音声なしで最後まで意味が通ること |
| 話者の絵 | 顔出しカット＋画面収録の抜きの2層。全編画面収録にしない |
| 画面収録 | ターミナルは文字サイズを上げる。**縦画面で読める行幅まで狭める** |
| BGM | 音量は声の -18dB 目安。ビートの強い曲は避ける（喋りが主） |
| 締め | 「次はこれをやる」の1行。毎回同じ定型文にしない |
| CTA | 保存誘導は R3・R5 のみ。全部に付けると効かなくなる |

**冒頭3秒のNG**: 「どうも、タクハです」「今日は Claude Code について話します」。
どちらも3秒を捨てている。名乗りは入れるなら中盤か最後。

## 5. 撮影・素材リスト

シリーズ通しで必要になる画面収録。先にまとめて録っておくと後がラク。

- [ ] `claude` を起動して、日本語で1行指示 → ファイルが実際に書き変わるまで（R1で使用）
- [ ] 同じ指示を出したときの、差分が画面に出る瞬間の抜き（R1・R2で使用）
- [ ] サブエージェントが複数並列で走っているときの進捗表示（R3のメイン素材）
- [ ] 雑な指示 / 具体的な指示 を並べて、出力の差が見える2画面（R4のメイン素材）
- [ ] `.claude/skills/` に SKILL.md を置いて、次から呼ばれるまで（R5のメイン素材）
- [ ] コード以外の作業をさせている画（資料整理・調査など）（R2・R6で使用）

画面収録は**等速で使わない**。1.5〜2倍に詰めて、待ち時間はカットする。ただし
「AIが自分で動いている」ことを見せたい数秒はあえて等速で残す。

## 6. 事実の扱い

台本の中で言い切ってよいこと（Claude Code の実際の挙動）:

- ターミナル上で動き、ファイルの読み書きとコマンド実行を自分で行う
- 日本語の指示で動く
- サブエージェントを複数立てて、並行して別の作業をさせられる
- `CLAUDE.md` にプロジェクトの前提を書いておくと、毎回説明しなくてよくなる
- Skills（`SKILL.md`）に手順をまとめておくと、条件に合った場面で読み込まれる
- MCP で外部ツール・サービスに接続できる
- ターミナル以外に、デスクトップアプリ・Web・IDE拡張からも使える
- コード以外の作業（調査、資料づくり、ファイル整理）にも使える

**言い切らないこと**:
- 料金・プラン・上限（変わる。触れるなら「詳細は公式で」に逃がす）
- モデル名や世代の断定（同上）
- 「エンジニアが不要になる」系の予測

## 7. 出したあとの運用

このリポジトリのスクリプトにそのまま繋がる。

```sh
./reel_post.sh accounts                                    # 投稿先の確認
./reel_post.sh check takuha                                # 接続確認（投稿前に必ず）
./reel_post.sh publish takuha ~/Movies/r1.mp4 "$(cat docs/consulting/claude-code-reels/captions/caption_r1.txt)"
```

キャプションは [`captions/`](captions/) に `caption_r1.txt` 〜 `caption_r6.txt` として
書き出してある。各台本の「投稿本文」とハッシュタグをそのまま入れたもの。**改行が入るので
シェルに直書きせず、必ずファイル経由で渡すこと。**

台本の投稿本文を直したら、キャプションも作り直す。`scripts.md` から機械的に起こせる。

```sh
python3 docs/consulting/claude-code-reels/captions/build_captions.py
```

投稿後の動画は `publish` が消すが、途中で失敗した分は残る。3日経てば `cleanup.sh` が
拾うので放置してよい。急ぐなら `./reel_host.sh clean takuha` を打つ。
