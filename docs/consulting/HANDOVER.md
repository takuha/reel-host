## 4. なぜそうしたか（作り直す前に読む）

ここが引き継ぎで一番失われやすい部分なので残す。**同じ結論に戻ってくる無駄を防ぐためのもので、
変えてはいけないという意味ではない。**

**8論点を6本にした。** 元動画のタイトルはそのまま8つの論点リストになっている。ただし
「ChatGPTとの違い」は「実行革命」と同じ話の裏表で、「言語化が全て」は「願望の質」の根っこ。
単体だと薄くなるので、それぞれ吸収して6本にした。判断の過程は `claude-code-reels/plan.md`
の表に残してある。

**投稿順を番号順にしていない。** R1→R4→R3→R2→R5→R6。掴み・刺さり・画の強さの3本を先に
出して勢いを作り、伸びより「残る」側を後半に置く設計。番号順に直すなら、その意図ごと捨てる
ことになる。

**料金・プラン・モデル世代を書いていない。** 意図的な除外。案件で聞かれることはあるが、
資料に焼き込むと次の案件でそのまま使えなくなる。口頭か別紙で補う前提。

**スライドの背景の質感を「点の並び」で出している。** pptx はグラデーション塗りとぼかしに
対応していない。光彩を半透明図形の重ね塗りで作ったところ、同心円の輪郭がはっきり見えて
しまったため、点描に差し替えた。**「ぼかした光彩にしよう」と思ったら、この道は塞がっている。**

**キャプションを手で写していない。** 台本の投稿本文とキャプションファイルが別々にズレるのが
一番厄介なので、`scripts.md` を正として機械的に落とす形にした（§5）。

## 5. 作り直しの手順

**スライド** — 中身の微修正なら pptx を直接編集してよい。レイアウトごと変えるなら
`claude-code-deck/build.js` を直すほうが早い。全ページが共通のヘルパーで組んであるので、
ファイル先頭の配色定数（`CYAN` / `VIOLET` / 背景色）を差し替えれば全ページのトーンが変わる。

```sh
npm install pptxgenjs
node docs/consulting/claude-code-deck/build.js docs/consulting/claude-code-deck/claude-code-summary.pptx
soffice --headless --convert-to pdf docs/consulting/claude-code-deck/claude-code-summary.pptx
```

**キャプション** — 台本の投稿本文を直したら必ず打ち直す。

```sh
python3 docs/consulting/claude-code-reels/captions/build_captions.py
```

**投稿** — キャプションは改行を含むのでシェル直書き不可。ファイル経由で渡す。

```sh
./reel_post.sh check takuha
./reel_post.sh publish takuha ~/Movies/r1.mp4 "$(cat docs/consulting/claude-code-reels/captions/caption_r1.txt)"
```
