# コンサル素材

案件で使い回す前提の素材置き場。1案件＝1ディレクトリで、**そのまま出せる成果物**と、
**次の案件で作り直すための材料**を同じ場所に置いてある。

| ディレクトリ | 何の素材か | 出せる形 |
| --- | --- | --- |
| [`claude-code-deck/`](claude-code-deck/) | Claude Code 入門の講義・共有用スライド（12ページ） | `.pptx` / `.pdf` |
| [`claude-code-reels/`](claude-code-reels/) | 同じ内容を短尺動画に落とした台本（6本）と構成資料 | Markdown ／ 投稿用キャプションは `captions/*.txt` |

どちらも元ネタは同じ YouTube 動画（【Claude Code完全入門】/ https://youtu.be/LRSSjGwsuv0 ）。
スライドと台本は**同じ論点の分解を共有している**ので、片方を直したらもう片方も見ること。

## 使い回すときの注意

**1. 出典の断りを外さない。** 元動画の本編は視聴できていない。タイトルに並ぶ論点と
Claude Code の実際の仕様から構成しており、動画固有のエピソードや数字は入っていない。
スライドの最終ページと `claude-code-reels/plan.md` に同じ断りがある。**引用元として
提示する形で配るなら、本編を確認して裏を取ってから出すこと。**

**2. 変わる情報を入れていない。** 料金・プラン・モデル世代は意図的に外してある。
案件によって「そこが聞きたい」と言われることはあるが、資料に焼き込むと**次の案件で
そのまま使えなくなる**。口頭で補うか、別紙にする。

**3. 事実の線引きは `claude-code-reels/plan.md` に書いてある。** 言い切ってよいこと
（Claude Code の実際の挙動）と、避けること（予測・断定）を分けてある。別のテーマで
素材を起こすときも、この線引きの作り方はそのまま流用できる。

## 別の案件に転用するとき

スライドは `claude-code-deck/build.js` を直すのが早い。全ページが共通のヘルパー
（見出し・カード・ターミナル風の枠・章番号のマーカー）で組んであるので、
**配色を差し替えれば全ページのトーンが一括で変わる**。クライアントの色に寄せるなら
ファイル先頭の `CYAN` / `VIOLET` と背景色だけ触ればよい。

台本のほうは `claude-code-reels/plan.md` の構成の作り方——論点を数え、単体で成立するか
判定し、弱いものを他に吸収して本数を決める——が中身より流用しやすい。テーマが変わっても
この手順は同じ。

## 素材を足すとき

`docs/consulting/<案件やテーマの名前>/` を切って、中に README を置く。README には最低限、
**元ネタ・成果物の一覧・使い回すときの注意**の3つを書く。ここの一覧表にも1行足す。
