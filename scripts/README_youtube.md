# YouTube 投稿の自動化

ローカルの mp4 をそのまま YouTube に送る。予約投稿（`publishAt`）まで API でできるので、
ここだけは本当に手が離れる。IG と TikTok は動画の選択が手作業なので、自動化できるのはここだけ。

栓は **`client_secret.json` を1回発行するだけ**。下の手順で15分。

---

## 1回だけやること（15分）

### 1. プロジェクトと API

1. https://console.cloud.google.com/ を開く（YouTube チャンネルと同じ Google アカウントで）
2. 上のバーからプロジェクトを新規作成。名前は何でもいい（例 `sns-auto`）
3. 「API とサービス」→「ライブラリ」→ **YouTube Data API v3** を検索して**有効にする**

### 2. OAuth 同意画面

1. 「API とサービス」→「OAuth 同意画面」
2. User Type は **外部**
3. アプリ名・サポートメール・デベロッパー連絡先だけ埋める。ロゴもドメインも要らない
4. スコープの画面では **`.../auth/youtube.upload`** を追加
5. テストユーザーに**自分の Gmail アドレスを追加**

> **ここが後で効く。**「テスト」のままだと **リフレッシュトークンが7日で失効**して、
> 毎週ブラウザで入り直すことになる。自動化の意味がなくなるので、
> 同意画面を **「本番環境」に公開**しておくこと（審査は不要。自分だけで使うぶんには
> 「確認されていないアプリ」の警告が初回に出るだけで、そのまま進めれば使える）。

### 3. クライアントを作って JSON を置く

1. 「API とサービス」→「認証情報」→「認証情報を作成」→ **OAuth クライアント ID**
2. 種類は **デスクトップ アプリ**
3. 作成後に JSON をダウンロード
4. こう置く：

```sh
mkdir -p ~/.config/youtube
mv ~/Downloads/client_secret_*.json ~/.config/youtube/client_secret.json
chmod 600 ~/.config/youtube/client_secret.json
```

### 4. ライブラリを入れる

```sh
pip3 install --upgrade google-api-python-client google-auth-oauthlib
```

### 5. 動くか確かめる

```sh
python3 yt_shorts_upload.py ~/path/to/video.mp4 --title "テスト" --privacy private --dry-run
```

`--dry-run` を外した最初の1回でブラウザが開く。許可すると `~/.config/youtube/token.json`
ができて、以降は勝手に更新される。**ここまでで栓は外れ。**

## 使い方

### 1本だけ、すぐ公開

```sh
python3 yt_shorts_upload.py ~/Movies/reel_08.mp4 --title "38歳まで、あと12日。"
```

### 1本だけ、予約投稿

```sh
python3 yt_shorts_upload.py ~/Movies/reel_08.mp4 \
  --title "38歳まで、あと12日。" \
  --publish-at "2026-08-15 21:30"
```

日時は**日本時間で解釈**する（`--tz` で変える）。予約すると公開までは非公開扱いになり、
指定時刻に自動で公開される。

### キャプションを別ファイルから

動画と同じ名前の `.txt` を隣に置いておけば勝手に読む。

```
reel_08.mp4
reel_08.txt   ← これが概要欄になる。1行目がタイトルにも使われる
```

### まとめて送る

```sh
python3 yt_shorts_upload.py --csv 予約シート.csv
```

CSV の列（`file` だけ必須）：

| 列 | 中身 |
|---|---|
| `file` | mp4 のパス。相対パスなら CSV から見た位置 |
| `title` | 省略すると概要欄の1行目 |
| `description` | 省略すると隣の `.txt` |
| `publish_at` | `2026-08-15 21:30`。空なら即時公開 |
| `tags` | カンマ区切り |
| `thumbnail` | 画像のパス |

いまの `投稿キュー_IG＆TikTok.csv` は列名が違うはず。合わせて変換するか、列名を教えてもらえれば
このスクリプト側を合わせる。

## 知っておくこと

**1日6本まで。** アップロード1本で API 枠を 1600 単位使う。既定の枠は1日 10,000 単位なので
6本で打ち止め。毎日1本なら余裕だが、31本を一気に流すことはできない。
枠が足りなくなったら Google Cloud Console から引き上げを申請する。

**ショート判定は自動。** 縦向きで3分以内なら YouTube 側がショートとして扱う。
`#Shorts` を付ける必要はない（付けても害はない）。

**サムネはショートに効かないことがある。** `thumbnail` を渡しても反映されない場合がある。
その場合は動画の1フレーム目がそのまま使われるので、頭の1コマを整えておくほうが確実。

**`token.json` は鍵そのもの。** これがあればチャンネルに投稿できる。共有しない、コミットしない。
`~/.config/youtube/` に置いてあるのはそのため。

**失敗しても止まらない。** CSV でまとめて送るとき、1本落ちても残りは続行する。
通信エラーは自動で5回まで待って再試行する。

## 動かないとき

| 症状 | 原因 |
|---|---|
| 毎週ブラウザが開く | 同意画面が「テスト」のまま。本番環境に公開する |
| `quota` と出て止まる | その日の6本を使い切った。太平洋時間の0時に戻る |
| `client_secret.json が見つかりません` | 置き場所が違う。`~/.config/youtube/client_secret.json` |
| 予約日時が過去です | `--tz` の解釈とずれている。既定は日本時間 |
| ライブラリが入っていません | 上の `pip3 install` を1回 |
